# V0.4 Run 原因分析 / 任务检查实施记录

2026-09-30。D0–D5（含D2V）完成。范围为Run Detail前端和全站基础白底；没有后端接口、SSE、持久化或算法数据语义修改。

## 使用方式

1. 打开一个Run。Execution、Task Outcome、Diagnosis和Capture仍为四类独立状态。
2. 在Trace工具栏点击“分析失败原因（RCA）”；已有报告时为“查看原因分析”等真实状态。此操作只打开Run面板，不启动作业。
3. 没有本次成功定位作业时，明确点击“定位异常步骤（本机）”。完成定位、模型配置可用且具备资格后，点击“预览并分析原因”。
4. 核对实际发送内容、模型、截断范围和快照，再点击“确认发送并开始分析”。关闭预览不发送；过期必须重新预览确认。取消已送达服务商的调用仍可能计费。
5. 阅读可能原因与相关证据；点击证据选择Trace对应Span/Event并打开原件。调用/返回都保持各自原件。
6. 切到“任务检查”查看上报测试/规则的结果、依据和来源。平台未复跑测试，RCA不能改变检查结果。
7. “分析记录”选择历史报告；“查看完整报告”读取原文；“更多资料”查看工程资料。Escape关闭抽屉，焦点回到入口，Trace视窗和选择保持。

运行中或现场采集未完整时，入口可发现但解释前置条件，不能发起新作业。仅任务检查失败时显示检查依据，不造工具错误。未知/冲突仍由原有Run投影表示。

## 视觉和时间表达

- 基础背景为#fff。正常共享时间区不铺逐行灰轨道；语义性hover/selected/error局部底色保留。
- Tool可靠区间实心蓝#2563EB；明确LLM事件点紫#9333EA；检查事件点琥珀#B45309；普通事件点蓝灰#64748B；失败红#DC2626。
- 选中用浅蓝行和深轮廓，保留类型/失败色，不将所有条重染蓝；引用以链接标记表达。成功结果的小图标仍为绿，类型色不代表成功。
- 18px条、8px点、42px行沿用原密度；四状态与顶部布局保留。检查面板初始180px、分析260px，自滚动/可收起/可调高，调整后尊重手动选择并适应视口限制。
- 只有唯一可靠correlation配对的Tool Call/Return成为逻辑Span；只有可靠双端来源时间才画区间。未配对调用/返回、日志、检查、RUN_END、单独LLM响应仍为点。没有时间则缺失；没有parent则平铺。
- 时间映射、父子规则、zoom/pan/fit/focus和原始duration没有改变。毫秒区间在整轮下仍短，使用既有缩放查看，不伪造长度或关键路径。

## 数据与后续限制

历史长摘要按实际溢出折叠并可展开，原文保留；本轮没有更改模型提示或额外调用模型改写。根因仍待验证，建议检查仍未执行。模型输出契约优化及真实模型环境验收仍是单独延期事项。

当前LLM大多只有响应事件、缺独立起止时间，不能画LLM duration区间。更多Agent/LLM Span仍需真实span_id/parent、kind、双端时间和时钟域。资料可说明缺失，UI不补造。

8000正式预览使用新的构建；隔离8001验收库不混入用户数据。当前未提交/推送新的增量，保留此前工作区改动。
