# V0.2 接入与演示

本版提供 CLI + 显式 Python SDK：使用真实的本地文件和进程操作验证采集、传输、状态和网页。示例 Agent 的决策是确定性的，不调用 LLM，不用于证明诊断或模型效果。

## 安装与运行

在项目根目录完成 README 中的 API／前端安装和构建，再安装 CLI：

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
.\scripts\start.ps1
```

保留平台终端，在第二个终端进入同一项目根目录：

```powershell
.\.venv\Scripts\agentops.exe run --sample-kind synthetic --goal "本地加法任务" -- .\.venv\Scripts\python.exe examples/local_agent.py --delay 4
```

CLI 输出执行网页链接和任务 ID。立即打开链接，即可看到现场事件持续加入。`--delay 4` 在两个工具之间留出观察时间。

演示“进程正常退出，但任务未通过测试”：

```powershell
.\.venv\Scripts\agentops.exe run --sample-kind synthetic --goal "本地加法任务" -- .\.venv\Scripts\python.exe examples/local_agent.py --fail --delay 4
```

如果要归到已有任务下，额外提供 `--task-id <上次输出的任务ID>`，目标和 sample-kind 必须保持一致。CLI 默认生成独立任务，不按名称猜测归组。安装并激活 `.venv` 后可直接写 `agentops run ...`；首版不会自动启动平台服务。

## 接入已有 Python Agent

1. 把已有工具函数加上 `@tool`，或者对工具注册表中的函数使用 `tool(existing_function)`。同步／异步函数均支持，返回值和异常继续传给原调用方。
2. 用 CLI 启动原 Python 入口；CLI 会给子进程提供 SDK 搜索路径和当前采集会话。子进程不需要安装 HGT、AgentTether analyst 或 repair 依赖。
3. 对独立测试结果调用 `verification`；没有检查时不填通过。Agent 的自述“完成了”不是独立验收证据。

```python
import subprocess
from agentops_cli import tool, verification

@tool
def run_project_tests():
    return subprocess.run(
        ["python", "-m", "pytest", "-q"],
        capture_output=True, text=True,
    )

# 在原 Agent 的工具注册表中使用 run_project_tests。
# 只有实际运行该检查后，才记录验收：
result = run_project_tests()
verification(
    "passed" if result.returncode == 0 else "failed",
    source="project-pytest",
    basis="项目测试命令的实际退出码",
    summary=result.stdout or result.stderr,
)
```

未加工具包装的程序用 `--adapter process-only` 启动；只能保证 stdout/stderr、退出信息与生命周期，不会自动识别模型调用或工具语义。SDK 不启用全局 monkey patch；在没有采集会话的普通启动下为无采集操作。

模型调用属于被监控 Agent 自身。需要记录已发生的非流式模型调用时，可在既有客户端边界调用 `emit('llm', 'MODEL_RESPONSE', input=..., output=...)`；SDK 仅保存事件，不发起模型请求。不应把密钥、完整客户端对象或认证 header 放进事件。本版没有 OpenAI/LangChain 自动集成，也没有 token 逐字流。

## 连接与数据状态

- 网页连接与 Collector 连接分别显示。15 秒没有采集心跳会标记失联，保留最后已知执行状态；不会据此认定任务失败。
- 正常退出、非零退出、Ctrl+C／Windows Ctrl+Break 分别记录完成、失败、取消。缺少验收证据时结果为 unknown。
- 数据 pending 表示还在接收或缺序号；complete 表示已收到声明范围内全部事件；partial 表示出现已知采集丢失。这里的完整性不保证工具适配覆盖了程序内所有操作。
- 只在全部声明事件到齐后生成快照哈希；快照绑定生产者、序号和规范化接收事件哈希，供后续诊断固定输入使用。
- 日志按行更新；超长字段会截断并带标记，未换行的超长输出会丢弃到下一换行并记完整性告警。已知密钥字段会脱敏，但不能保证识别任意格式的敏感数据。

## 断线与补传

CLI 从启动目录下的 `.agentops/spool/` 保存本机 outbox（受 Git 忽略）。服务短暂不可用时继续运行 Agent 并保留未确认数据。排空最多约 10 秒加当前请求超时，仍未完成时打印具体补传命令：

```powershell
.\.venv\Scripts\agentops.exe resume ".agentops/spool/<执行文件>.sqlite3"
```

补传沿用事件 ID，重复接收不会增加事件数量。没有 finish 的硬杀记录补传后仍缺少执行结束证据，不会伪造成功。会话写入凭据有效期 24 小时；超期无法自动续传，请保留原始本机 spool，延期恢复不属于本版能力。

边界：每轮服务端最多 20,000 事件；本机 spool 最多 19,000 事件、32 MiB 的事件正文，达到任一限制后停止追加并计数告警。数据库文件实际占用还包含索引和元数据。spool 为恢复保留已发送记录与会话凭据，只供当前本机用户使用，勿分享或提交。

## 能力核查与真实模型兼容性（pending）

| 项目 | 当前状态 |
|---|---|
| 确定性工具型 Agent，真实文件与测试操作 | 核心验收已覆盖；标记 synthetic |
| Python 同步／异步显式工具包装、嵌套父调用、异常 | 已支持并测试 |
| 进程日志、退出码、SSE、恢复、历史回放 | 已接入 |
| AgentTether 格式语义 | 沿用 tool_call/tool_return/correlation_id，未复制第三方源码或启用其全局 patch |
| AgentTether 原采集直接复用 | 暂未启用；Observer 会导入报告模块，算法目录未确认独立再分发许可证 |
| 真实 LLM Agent 兼容性 | pending；不阻塞 V0.2 核心交付 |
| 模型 SDK 自动采集、token 流、任意 Agent 支持 | 未实现 |
| analyst/HGT/repair 推理 | 未接入，不属于 V0.2 |

用户提供已有授权／本地模型后，兼容性验收流程：记录 Python／框架／模型版本 → 显式包装实际工具 → 用 CLI 启动原 Agent → 检查任务完成前的事件可见性 → 校验工具输入／输出／异常及独立测试证据 → 对照不采集时的执行行为。成功和失败各一条，记录覆盖缺口；不把确定性测试结果转换成真实模型验收结果。
