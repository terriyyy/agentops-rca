# V0.4 Run-centric 工作台开发计划

状态：已完成（2026-09-27）。本计划承接产品审查与信息架构结论；不新增 Investigation 实体，不变更采集、验收与诊断事实语义。结果见 [V0.4 验收记录](v0.4-validation.md)。

## 用户路径

首页接入说明 → 终端启动 Agent 并获得 Run 链接 → 首页/深链观察实时 Run → 查看明确的失败事实和原始证据 → 手动运行离线定位 → 人工预览并确认付费 RCA → 将报告当作待验证假设 → 查看独立验收 → 在相同 Task 下再次执行并比较。

## 状态契约

- `origin`（进入方式）与 `sample_kind`（数据性质）同时展示；实时合成样例可以同时具有两种标签。
- `execution_status`、`outcome_status`、诊断作业/报告、`capture_integrity`、网页 SSE 连接各自独立。执行完成不能推出验收通过；引擎可用不能推出已诊断；模型报告不能改写验收。
- Run 诊断投影保留“当前/最新作业”和“已有报告”两个维度。同轮旧报告存在而最新作业失败时同时显示两者；HGT 只代表离线定位；导入报告标明非本机重算。
- 失败线索仅来自明确的非零/异常执行、失败工具/错误事件和未通过的独立验收。每条线索引用原记录；找不到具体错误时不编造根因。
- 数据不完整时报告采集限制。网页断线与采集器失联均不自动更改进程结果。

## 阶段与交付

1. **状态投影**：增加后端只读 Run 概览与共享投影。首页有界返回运行中、需处理、最近记录；Run/Task 用同一诊断状态逻辑。测试覆盖已生成诊断、HGT-only、导入报告、旧报告+新作业失败、执行完成但验收失败、合成实时和采集不完整。
2. **首页**：`/` 独立于 `/tasks`；先提供真实接入与演示分流，再展示运行中、需处理和最近 Run。每条入口直接指向 Run；历史任务目录和导入作为次级入口。页面不执行 Agent 命令。
3. **Run Detail**：2026-09-28 已续改为轨迹主视图＋选中事件详情＋Run 级调查 dock，取代纵向章节。完整轨迹默认可见，根因假设与独立验收分别呈现；运行资料按需展开。保持 SSE、证据原文/哈希、HGT→预览→人工确认的调用链。实现及数据边界见 [Run Workspace](v0.4-run-workspace.md)。
4. **Task Detail**：按明确 task_id 的运行历史与对照组织；显示前后 Run 的结果和诊断进度，不从顺序推断修复因果；提供保留 task_id 的接入说明。
5. **验收**：API 语义回归、浏览器关键路径、窄屏检查、前端构建和文档。模型请求在浏览器回归中拦截/模拟；不主动调用付费模型。

## 不包含

自动修复/重试、服务端执行用户上传命令、真实模型 Agent 兼容性验收、新 Investigation 表、跨轮干预因果推断和生产级多用户部署。
