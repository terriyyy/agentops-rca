# V0.4 补充调研：纯白底面与实心 Timeline

日期：2026-09-30。状态：调研、规划及D2V实施完成。下文保留调研时的问题与建议；作为原因分析/任务检查开发计划的补充，不重做页面骨架或时间轴逻辑。

## 实际问题

- styles.css 的根背景为 `#f7f8fa`，使未被白色容器覆盖的页面底面偏灰。run-console 已是白色，但表头、dock栏和大块代码区域叠加浅灰会继续影响整体观感。应检查最终 computed style，不能只改根变量就宣布完成。
- 当前普通条 `#a9ccd3`、失败条 `#e4aaa0`、选中条 `#91b4dd` 本身低饱和；条的 CSS 没有统一透明度问题。改成 opacity:1 并不能单独解决。
- selected 将正常条改成同一蓝色，可能削弱类型区分。共享网格虽已存在，但过浅的条让网格/背景比数据更显眼。

## 背景方案

- 全站最外层基础画布、body/应用壳主背景统一为 `#ffffff`。这是用户新增授权的全站基础样式例外，不修改其他页面布局/业务组件。
- Run主工作区、Trace列表/共享轴底面、Selected Event和底部面板底面为白色；时间刻度表头、dock栏尽量同为白底，以文字层级和细分隔建立边界。
- 保留有语义的局部底色：hover、selected、错误区、少量输入/禁用状态。不得为了“纯白”删除错误辨识度和选择态。
- 不全局把 `--surface`、所有灰色、所有pre或所有组件背景粗暴替换成白色；先区分基础画布与交互/代码表面。大面积灰盒优先减弱，代码/原件仍需清楚可读。

## 条形与颜色方案

实心是指不透明、明确填充，不是加宽耗时或铺满整行。区间仍从真实start offset到真实end，共享轴不变，禁止恢复每行progress轨道。

以下是本项目建议初值，不是从竞品提取的品牌色；实施时按两尺寸截图和对比度检验微调。

| 已有可靠类型/语义 | 建议颜色 | 表达 |
| --- | --- | --- |
| Tool / 通用SPAN | `#2563EB` 蓝 | 实心区间；当前主要可靠Span来源 |
| 已明确标注的LLM | `#9333EA` 紫 | 有可靠双端时间才是区间；只有响应事件仍是点 |
| 已明确标注的Agent | `#0E7490` 青蓝 | 同样受真实数据规则约束，不造根Span |
| 检查证据事件 | `#B45309` 琥珀 | 类型点，不能表示检查已经通过 |
| 普通Event / Log | `#64748B` 蓝灰 | 实心点/菱形，不画duration |
| 明确失败 | `#DC2626` 红 | 默认覆盖区间为红色，加错误图标/终点；原类型由标签保留 |

- 类型颜色不代表成功。成功继续使用小型绿色结果图标/状态，不把所有成功Span刷绿。
- selected：浅蓝整行 + 深色细轮廓；正常条保留类型色，失败条保留红色。hover只影响行/轮廓，不把条洗淡。
- referenced：链接图标/明确提示；不用更淡的整行色替代证据关联，不覆盖selected/failed。
- 条保持约18–20px高、明确边界、1–2px小圆角，先沿用42px行高，不靠大卡片加重。普通点建议7–9px，失败点配图标/可访问文本。
- 不使用渐变、玻璃效果、常态半透明条、随行随机颜色、服务名哈希调色或层级逐层变淡。层级由可靠树线/缩进表达。
- 现有工具名即使叫litellm.completion，也不能仅凭名称改成LLM Span；按实际类型和可靠数据规则展示。

## 时间语义与边界

- 可信唯一correlation的Tool Call/Return才是逻辑Span；真实可靠双端时间才画区间。无可靠duration/start-end仍是点，即使来源有耗时文本也不猜开始时间。
- stdout/stderr、OUTCOME_EVIDENCE、RUN_END、单独LLM_RESPONSE仍按真实时刻表示。没有时间显示缺失，不随意放到0ms。
- 毫秒跨度相对整轮确实短：使用已有zoom/focus/本页fit，不用夸大条宽伪造长耗时。最小像素标记只供可见/可点击，真实duration和tooltip保留。
- 不增加critical path、父子、等待/执行段、模型token流等当前不存在的数据。

## 实施与验收

并入主计划新增 D2V：D0基线 → D1状态 → D2入口/容器 → D2V白底与实心时间条 → D3内容/证据 → D4预览 → D5回归。

预期改动：styles.css基础画布；run-workspace.css局部底面、颜色token及状态；必要时trace-timeline.tsx只增加已知类型的展示class/data属性。trace-model的配对、时间映射、parent规则及后端不修改。

验收：

- computed style确认全站基础画布、Run正常行/轴为 `rgb(255,255,255)`；首页/Task/导入页只检查底色，不改变其结构。
- Span可见条为实心，opacity为1且填充alpha为1；hover/selected不淡化、不统一改蓝，失败条保持失败色。
- 条/点对实际白底或选中背景目标至少3:1，普通正文目标4.5:1；错误/类型/选择另有文本、形状或图标，不仅依赖色相。
- 刻度/网格轻于条但可读；zoom/fit及原有区间坐标断言通过；类型/失败样例截图中没有progress轨道。
- 保留missing time、极短Span、未知层级、跨页证据与实时跟随回归；白底不使分栏/日志/禁用状态无法区分。
- 同Run同视口before/after（1366×768、1920×1080）检查白底、长短条、失败/选中/引用组合。没有真实LLM/Agent区间时只验证点与类型，不伪造真实演示截图。

实施更新：上述要求已并入D2V完成。基础背景computed style为rgb(255,255,255)，条形opacity为1；同Run两种桌面尺寸before/after条宽一致，类型/错误/选中和时间几何浏览器回归通过。截图与验证见[实施说明](v0.4-run-analysis-implementation.md)。
