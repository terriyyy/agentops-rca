# V0.4 Run Detail：原因分析与任务检查开发计划

日期：2026-09-30。状态：D0–D5（含D2V）实施和验收完成。

依据：[已完成的产品调研与方案](v0.4-run-analysis-panel-proposal.md)。本文件保留阶段任务与验收标准，不重新设计 Run-centric 信息架构。用户授权实施后已完成代码、测试与截图任务，结果见[实施说明](v0.4-run-analysis-implementation.md)。

补充要求（2026-09-30）：全站基础画布改为纯白，Run Timeline改为实心且清晰的类型色/失败条。调研、色值建议与验证边界见[白底与实心Timeline补充方案](v0.4-white-surface-solid-timeline.md)，并入D2V，不重写Timeline逻辑。

## 1. 目标与完成条件

让新用户在 Run Detail 首屏能发现“分析失败原因”的能力，并在当前 Trace 工作区看懂：发生了什么、可能原因、相关证据、下一步检查、任务是否达标。

完成条件：

- RCA 主入口在首屏可见，进入准备流程，不因进入页面、点入口或刷新状态而调用模型。
- 底部主面板只有“原因分析 / 任务检查”两种用户目的；报告历史和技术资料可追溯但不占同等视觉权重。
- 原因结果默认是有限长度的摘要和可定位证据，完整原文可按需读取；不擅自增强结论。
- 任务检查明确是上报测试/规则的结果，独立于诊断，不暗示平台已重新运行测试。
- Trace、时间轴、选中事件详情、证据定位和实时行为完整保留。
- 桌面 1366×768 与 1920×1080 均能完成查看失败、预览、检查和证据回跳，没有整页长报告或关键按钮被遮挡。
- 全站基础画布纯白；Run共享时间轴上实心条清晰，hover/selected保持类型和错误语义，真实时间比例不变。

## 2. 固定边界

必须保持：

- Execution completed ≠ Task passed；Diagnosis ≠ Validation。
- RCA 结论是待验证的假设。任务检查通过也不自动证实根因。
- live / imported / synthetic 来源、Capture Integrity、原始证据与报告来源独立保留。
- 模型调用必须先展示实际发送内容，用户确认后才提交；没有自动调用或自动付费重试。
- 不新增 Investigation 数据实体、不变更事件/报告/验收的持久化语义。
- 不重构 Header、Sidebar、首页、Task History、Trace Timeline布局/逻辑或设计系统。新增的全站纯白基础背景允许最小共享样式调整；Run Timeline允许局部颜色/条形/选中视觉调整。
- 不伪造父子关系、时间、工具配对、actual/expected、因果链、置信度或已执行检查。

本轮后续实施以复用现有前端逻辑和 API 为主，不需要数据库迁移或新增后端接口。只有已被接口返回的字段存在类型遗漏时，允许补充前端类型；字段缺失采用明确空状态。模型输出契约改进另列延期事项，不属于完成本计划的前置条件。

## 3. 页面与组件职责

```text
Run Header + 四种独立状态                       保持现状
Trace Toolbar：现有工具 + [分析失败原因（RCA）]  Run级主动作
Trace + Selected Event Detail                  保持现状
原因分析 | 任务检查·状态 | 分析记录(n) | 更多资料 | 收起
限高、自滚动、可调整的工作面板
```

主入口明确作用于“本次运行”，不作用于搜索结果或当前选中事件。失败上下文可提供同一入口；右侧事件详情只显示轻量“此事件被分析引用”关联。

## 4. 数据来源与显示规范

| 展示信息 | 现有来源 | 规则 |
| --- | --- | --- |
| 执行/任务/Capture状态 | Run及后端投影 | 继续使用既有结论，不从诊断正文重算任务状态 |
| 当前推荐报告 | run.insight.diagnosis.featured_report + diagnoses | 复用当前投影；报告不存在/刷新时显示真实加载状态，不伪称尚未诊断 |
| 当前作业阶段 | diagnosis jobs / capabilities | 与报告分别呈现；新作业失败时旧报告仍可读 |
| 已知失败事实 | 原始事件及 outcomes | 工具异常、检查失败分开；只有检查失败时不造工具错误 |
| 可能原因 | summary / findings.description | 保留原意和不确定性；历史自由文本不由前端语义改写 |
| 下一步检查 | verification_suggestion / guidance | 标记建议尚未执行；不是新的测试结果或执行按钮 |
| 不确定性与限制 | boundary / report原文 | 影响判断/行动的限制不能仅因收起正文而消失 |
| 相关证据 | findings.evidence / evidence_chain / evidence API | 引用不是已证明的因果图；保持解析状态和原始ID |
| 任务检查 | outcomes + Run outcome_status | 展示依据、来源、authoritative语义；冲突使用既有结果，不自行取最新 |
| 原始模型内容与元数据 | preview / report / jobs | 哈希、版本、快照、JSON保留技术入口；发送预览中相关信息仍必须可核对 |

普通界面术语：原因分析、可能原因·待验证、任务检查、相关证据、下一步检查、分析记录、更多资料。HGT、analyst、adapter、SHA-256、provenance 等工程术语放入资料或必要的预览明细。

证据行优先显示“#步骤 工具名 · 调用/返回/事件”，仍绑定 evidence_id/event_id。聚合到同一个工具 Span 的调用与返回可各自追溯，不因合并而丢原件。未解析引用显示来源/解析状态和原件入口，不猜测对应步骤。默认显示关键引用时必须有“其余 n 条/全部证据”入口，不能静默只取前三条。

长文本降级策略：用已有结构字段分块；历史长 summary 保留原文并提供展开，明确默认展示的是摘要片段。不按标点硬拆为“根因”，不再调用模型做二次摘要，不把示例文案替换成真实诊断。若无法可靠区分“事实”与“假设”，只把原始失败事实放事实区，报告原文留假设区。

## 5. 操作、状态与接口边界

状态是多维组合，不合并成一个“成功/失败”标签。以下动作名称为 Run 局部展示，不改变 API 枚举。

| 实际条件 | 首屏与面板表现 | 点击是否执行 |
| --- | --- | --- |
| running / execution unknown / live capture未完整 | 入口仍可发现，说明真实前置条件；已有历史结果保留来源 | 只查看/准备，不能发起新作业 |
| 已结束、无成功定位作业 | 分析失败原因 → 定位准备 | 首屏点击不执行；点击“定位异常步骤（本机）”才POST定位 |
| 定位queued/running | 正在定位异常；真实状态及取消入口 | 不重复提交 |
| 仅定位结果 | 继续分析原因；展示定位线索 | 有配置及前置条件才获取预览 |
| analyst未配置/不可用 | 明确不可用原因；保留定位与已有报告 | 不创建模型作业 |
| 有有效预览 | 显示本次发送内容、模型、范围、截断情况 | 只有“确认发送并开始分析”执行 |
| analyst queued/running | 正在分析；可读旧报告，可取消 | 禁止重复确认和自动重试 |
| 有RCA报告 | 查看原因分析；待验证结论与证据 | 查看不执行；再次分析走完整准备/预览流程 |
| 只有导入/历史报告 | 查看历史分析；明确来源 | 阅读不视为本平台新调用 |
| 最近作业失败/取消且有旧报告 | 本次分析未完成 + 上一份报告 | 错误与旧结果共存；重试必须手动 |
| 任务通过或未知、无失败事实 | 查看运行分析/检查状态，按真实资格提供操作 | 不制造失败或劝导自动分析 |

优先显示当前活动作业；已有报告、最近失败提示、可再次分析资格仍作为独立信息保留。用户选定旧报告后刷新不静默切走；切换到另一 Run 时清理旧 Run 操作状态。首次默认打开合适的短面板，之后 SSE/轮询不覆盖用户的 Tab、收起、选择、过滤、时间视窗或高度选择。

接口复用：

- GET `/runs/:id/diagnoses`、`/runs/:id/outcomes`、现有 capabilities/jobs：读取状态。
- POST `/runs/:id/diagnosis-jobs`：用户明确启动本机定位，保留 request_id。
- GET `/runs/:id/analyst-preview`：读取真实发送预览，不调用模型。
- POST `/runs/:id/analyst-jobs`：人工确认后发送 request_id、preview_sha256、hgt_diagnosis_id。
- POST `/diagnosis-jobs/:id/cancel`：沿用现有取消行为，不能承诺已到服务商的调用未计费。
- GET `/evidence/:id`：复用现有证据解析与原件读取。

切换 Tab/关闭资料不意外丢弃未提交预览；关闭预览不提交。数据或定位版本变化造成预览过期时，沿用后端校验，提示重新获取并再次人工确认；不自动替换快照后发送。抽屉只读操作与模型确认按钮明确分离。

## 6. 分阶段实施与验收

顺序：D0 → D1 → D2 → D2V → D3 → D4 → D5。所有阶段当前为 pending。

### D0：固定现有行为与验证样例

任务：核对真实 Run 字段、既有测试及当前未提交改动；记录同一 Run 的 before 截图、四种独立状态、报告选择与预览行为。准备无模型请求的确定性/Mock场景。

验收：同一失败 Run、仅检查失败 Run、长历史 Run 可复现；明确当前11项浏览器回归基线；没有覆盖前一轮 Timeline 增量，没有读取/记录密钥。完成记录仅证明基线，不证明后续功能。

### D1：统一 Run 分析状态与操作生命周期

任务：整理 DiagnosisControls 的读取/操作为可复用控制层，接入 RunPage/Workspace；入口和面板读取同一当前Run状态，保持现有诊断投影优先级。区分活动作业、推荐报告、用户选择报告和前置资格。

验收：首次有报告不显示“未分析”；旧报告与新作业失败共存；不新增重复状态源/失控轮询；换Run不会提交旧预览；刷新不覆盖手动选择；原接口、request_id及快照绑定保持。

### D2：首屏入口与底部两种主面板

任务：Trace工具栏增加Run级动作，失败上下文接同一动作；主Tab改“原因分析/任务检查”；报告计数移动至分析记录；Technical进入更多资料。保留可收起、自滚动、鼠标/键盘调高；初始高度按模式和可用空间确定，手动调高后尊重用户选择。

验收：1366px首屏可见入口，不挤掉现有Trace操作；点击只开准备/结果；只有一条检查不留巨大空框；Trace/详情仍能回看；主面板不形成整页长滚动。建议分析220–280px、检查140–200px作为初测范围，最终以两尺寸验证为准。

### D2V：纯白基础背景与实心 Timeline 条

任务：依据补充调研将全站基础画布和Run正常工作区改成#fff；去掉Run表头/dock等无必要的大面积灰底；类型条采用不透明中高饱和填充，失败红、选择轮廓独立。保留局部hover/错误/选择底色及原有密度，不改Span聚合或线性时间坐标。

验收：computed style确认基础画布白色；正常/选中条均不透明、失败不被选择态洗成蓝色；条/点对实际底色目标3:1、正文4.5:1；普通事件仍为点，缺时间不绘制；共享刻度、zoom/fit和短区间语义不变。两桌面尺寸同Run截图中不再有灰色progress轨道，首页/Task等只有基础底色改变。

### D3：结果、证据与检查内容

任务：原因面板采用事实/可能原因/证据/下一步结构，全文按需阅读；证据行可读并复用回跳；检查面板采用紧凑检查行，说明依据和来源，失败展开。分析记录支持选报告，所有旧技术数据在次级资料可访问。

验收：未经证据支持的原因不写成事实；重要不确定性可见；不把5份报告叫5个根因；调用/返回原件都可访问；未知/冲突/历史来源有真实表达；检查结论不随报告选择变化；缺实际返回值明确缺失。

### D4：定位准备、发送预览与人工确认

任务：用易懂动作呈现既有定位→预览→确认流程，显示缺配置/不具备资格的原因。实际发送内容默认按需在有界面板/抽屉阅读，但用户确认前能够核对完整内容与截断；作业状态和错误不伪装成模型推理过程。

验收：缺HGT成功作业不绕过预览前提；首屏/Tab/证据/SSE不POST模型；关闭/取消预览不发送；人工确认只提交一次，保留幂等和哈希校验；过期预览不能悄然重新生成并发送；无自动重试。使用Mock验证，不调用真实付费模型。

### D5：回归、截图与使用说明

任务：生产构建；运行适配后的Run Workspace和CLI/SSE测试；仅为新增交互或语义风险补回归，不写纯实现镜像测试。保存相同Run的before/after，在1366×768和1920×1080检查主操作、焦点、抽屉、自滚动、缩放和证据回跳。更新workspace/validation说明。

验收：构建与相关浏览器测试通过；原有Trace行为不断；键盘可切Tab/选报告/关闭抽屉，焦点回到触发点；所有证据及技术原件仍可追溯；产品代码未越出本计划范围；测试不触发真实模型。记录通过数量和截图路径，不直接沿用旧轮“11/11”作为本轮结果。

## 7. 必测场景

| 场景 | 必须确认 |
| --- | --- |
| 执行完成、退出码0、任务检查失败 | 执行完成与任务未达标并列；入口明显，不造进程失败 |
| 失败工具Span | Error仍在Selected Event；分析不塞进事件详情 |
| 没有异常Event、只有检查失败 | 默认能看到检查依据并进入原因分析 |
| passed / unknown / running | 不把未知当成功；运行中不自动建作业 |
| live capture partial/pending + imported | 资格依现有条件；来源如实，导入不冒充本平台重跑 |
| 多份报告、最新作业失败/取消 | 用户可读旧报告，计数正确，错误不覆盖已存在分析 |
| HGT未完成、模型未配置 | 准备步骤和限制易懂，不绕过API资格 |
| 获取/关闭/确认/过期预览 | 确认前零模型POST；过期需重新预览确认；双击不重复 |
| 证据跨页、已筛选、指向同一Span调用/返回 | 定位逻辑与原件均保留；关闭资料不重置时间视窗 |
| 引用未解析/不唯一、无时间/parent | 明确降级，原件可读；不猜配对和层级 |
| 检查记录缺失/冲突/来源为报告 | outcome投影保持；不冒称独立测试或补实际值 |
| 历史长报告、关键否定/边界 | 原文完整可读；收起不制造更强结论 |
| SSE刷新、实时跟随、搜索筛选、zoom/fit | 不夺取当前面板/选择/滚动；Trace交互不退化 |
