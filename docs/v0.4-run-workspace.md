# V0.4 Run Detail 调试工作台

## 2026-09-28 增量：Tool Execution 与 Run-level Investigation Panel

保持既有 Header、Trace 工具栏、左右 split pane、实时跟随及独立状态。UI 将同一非空 `correlation_id` 下唯一的同名 Tool Call / Tool Return（调用位置先于返回，明确父 ID 不冲突）显示成一行 Tool Execution。点击后右侧分别查看 Call / Arguments、Return / Exit code、stdout、stderr / Error，并有两个原件入口。报告引用 call 或 return 都定位到该逻辑行，但打开的仍是所引用的原始证据。无可靠配对的调用/返回、stdout/stderr 日志、`OUTCOME_EVIDENCE` 和 `RUN_END` 保持普通事件；不从时间邻近推断关系。

底部 dock 保持限高、独立滚动和可收起，三个常驻页签为“根因假设 / 独立验收 / 技术详情”。假设默认只有摘要、待验证或定位/历史来源状态、前三个关键证据引用、适用边界与简短建议；完整报告需手动展开。HGT/RCA 作业历史、算法/模型/Adapter、输入快照与 SHA-256、原始 HGT/RCA 输出、JSON、provenance 和运行文件集中在默认折叠的技术页。独立验收继续单独显示结果、来源、依据和原始记录，诊断不写入任务验收。模型发送预览仍在手动诊断区，确认前不发请求。

若相同时间戳或来源 duration 与时间差不符，逻辑行不画时间区间；没有来源 duration 时不把同一时刻当成 0ms。未来若需真正完整 Span Tree / Waterfall，仍需服务端输出经核准的 span/link 关系、独立起止时间与时钟域、LLM 与工具细分字段；本次 UI 没有补造。

2026-09-28。只重构 Run Detail 前端，不新增业务对象或改写 API、事件、SSE 和历史记录语义。

## 页面与组件

- `RunPage` 继续读取详情和合并 SSE，交给 `RunWorkspace` 呈现。
- Header 同时显示 Execution、Task Outcome、Diagnosis、Capture。Task Outcome 和 Diagnosis 是打开 Run 级面板的快捷入口，两个状态没有相互覆盖关系。来源 `live/imported` 与样例性质 `synthetic/...` 分别保留。
- Trace 默认可见，支持搜索、事件类型、仅异常、失败定位、50 行分页和现场跟随；API 每批读取最多 200 条，初次完整读取当前 Run，后续只补充追加事件。当前契约每轮最多 20,000 条；更大规模需要后续服务端索引与按需读取，不在本轮新增。
- `Selected Event Detail` 常驻右侧，选择一行不跳页面，也不打开阻断操作的 modal。错误优先、唯一关联的工具调用输入及返回可交叉核对，两条原始证据可分别打开，完整 JSON/校验值折叠。不同事件内容按原始字段展示，缺失数据不生成占位数值。
- Run 级 dock 内分开保留根因假设、独立验收和技术详情；支持拖动/键盘调整高度及收起。切换页签不会丢失尚未确认的模型发送预览。
- 报告引用的证据若能解析到本轮事件，则清除过滤、展开真实祖先、切换到目标页、选中并打开原件；未解析/歧义/Run 级证据只显示原件，不猜测对应事件。

旧 `FailureEvidence`、`TracePreview`、`InvestigationRail`、`RunRelations`、独立 `TracePanel` 的 Run 页面实现已移除或合并。`DiagnosisPanel/ReportView`、`OutcomePanel`、`Overview` 复用原数据逻辑，样式收紧到 dock；其他页面继续使用原 `EvidenceDrawer`。Task 历程仍负责多轮关系。

## Trace 数据真实性

1. `source_span_id` / `parent_source_id` 已由当前后端返回，本轮仅补充前端类型。只有父 ID 唯一可解析且没有未解析关系、自环、循环时才启用来源关系树。普通事件不因位于两个工具事件之间而成为子节点。
2. 没有可靠关系时平铺；过滤时也平铺显示匹配事件，避免伪造完整父子链。
3. 时间轴使用有显式时区的 `occurred_at`，原件没有时间时不使用导入时间。缺少时间的事件显示空值，只有一个时间点时不建立时间尺度。
4. 持续时间条只来自本轮唯一 `correlation_id` 配对的同名调用/返回，调用先于返回、两个时间戳有效，且给出的 `duration_ms` 与时间差一致（允许采集误差）。不一致只画事件时间点，记录耗时仍原样显示。LLM 只有 duration 时不会倒推 start_time。
5. 来源时间不能保证跨生产者时钟同步；时间轴、父子关系、异常位置均不能证明根因。

未来真正通用 Span/Waterfall 需要稳定且唯一的 span_id/parent_span_id、明确的 span kind、start_time/end_time、duration 单位及时间戳锚点语义、生产者/时钟域和明确调用关联。LLM model/token、工具 stdout/stderr 等有原始字段才展示；不在本轮补造。

## 页面状态

- running：跟随最新；用户选择旧步骤或筛选后暂停跟随；已有独立检查则如实显示，否则任务结果未知。诊断 eligibility 延续原规则。
- failed：仅明确失败的工具/错误事件出现 failed 行及可展开日志；进程失败与任务验收分别显示。
- passed：独立验收通过不抹掉轨迹中的工具失败，也不证明某个诊断正确。
- unknown：没有验收证据仍未知，退出码 0 和诊断报告均不会改写它。
- 只有独立验收失败：默认打开验收面板，轨迹不造失败步骤，右侧说明未记录失败执行事件。
- Diagnosis none/running/report/latest job failed：没有报告提供手动入口；作业进行中或最近作业失败仍保留已有报告；RCA 一律标记待验证，建议验证没有执行就不算独立验收。

## 查看

按 README 启动后，在工作台打开任意 Run。先选择工具步骤核对右侧内容，再打开底部根因假设点击证据反向定位，或切换独立验收查看检查来源。桌面 1366×768 与 1920×1080 已按同屏工作区验收，390px 使用上下排列回退。
