# V0.2 开发计划：实时运行监控闭环

更新日期：2026-09-20。状态：核心实现与验收 complete；真实模型 Agent 兼容性 pending。用户编码期间明确采用确定性 Python 工具 Agent 完成主链路，不以模型环境为前置条件。可执行用法见 [接入说明](v0.2-agent-integration.md)，结果见 [验收记录](v0.2-validation.md)。以下保留设计及关口，总路线见 [第一版开发计划](v1-development-plan.md)。

## 1. 目标与使用流程

面向单用户、本机代码／运维 Agent：用户通过命令启动一种受支持的 Python Agent，取得执行链接，在网页上实时查看工具调用、日志、错误与执行状态，结束后仍能回放和定位证据。

已实现入口（平台服务需先启动，CLI 需先安装；该示例显式标记 synthetic）：

```powershell
agentops run --sample-kind synthetic -- python examples/local_agent.py
```

一次命令创建一个 Run；同一任务的再次执行通过显式任务 ID 归组，不能仅凭任务名称自动合并。CLI 返回本次 Run 的网页链接，透传子进程输出与退出码。

V0.2 的成功标准是实时链路成立，不依赖 HGT 权重或付费模型。历史导入、证据查看与两轮对照继续可用；历史数据和现场数据明确区分。

## 2. 支持范围与非目标

| 范围 | 本版约定 |
|---|---|
| 首个环境 | Windows、Python 3.12、单个串行工具型 Agent 进程；其他环境需验证后再声明支持 |
| 基础采集 | 子进程 stdout/stderr、异常、退出码与生命周期 |
| 结构化采集 | 一种明确适配的 Python Agent 工具入口：调用参数、开始、结束、返回、耗时、错误、关联 ID |
| 接入方法 | 优先评估 AgentTether 已有 instrumentation；不适用处用轻量 SDK／显式工具包装，记录所需改动 |
| 模型调用 | 首轮核查明确非流式调用的覆盖范围；缺少模型接入时如实显示，不影响工具链路验收 |
| 展示 | 增量事件与日志；不承诺模型 token 逐字输出 |
| 可靠性 | 有界缓存与补传、幂等接收、网页重连、正常结束／失败／中断／失联区别 |
| 验收结果 | 接收有来源的验收证据；无独立依据时 unknown，不能由退出码推断任务通过 |

通用命令包装只保证进程级观测；工具和模型语义依赖适配，不能宣称任意 Agent 零改动接入。通用采集层称 Collector，PROBE 保留为算法／历史格式专名。

本版不纳入完整 AgentTether/HGT 推理、自动修复重试、任意框架兼容、子进程树的全面语义采集、eBPF、系统事件因果推断、多租户、云部署或分布式队列。

## 3. 模块与数据流

```text
CLI → 创建 Task/Run/采集会话 → 启动受支持的 Python Agent
Agent 工具包装 + 进程输出 → Collector → 本地待发送队列 → 批量接收 API
接收 API → SQLite 事务持久化 + 增量关联 → SSE → 现有执行详情页
CLI → 排空待发送数据 + 结束记录 → 页面终态及完整性状态
```

- CLI 负责运行编排、链接、输出转发和信号处理，不解析算法报告，不在服务器执行上传的命令。
- Collector 负责事件标识、采集、最小必要脱敏和有界队列；采集错误不能被伪装成 Agent 业务错误。
- Ingest 服务负责会话校验、格式校验、幂等与持久化；只在事务提交后确认接收。
- Correlator 复用 Run 内精确 ID 关联；缺返回的调用保持可见，后续返回到达时再关联。重复源 ID 保留歧义，不能任取一条。
- SSE 负责发送已持久化的变化通知，前端查询／合并现有数据；不在前端另建一套事实状态。
- Storage 沿用 SQLite；增加可升级的数据库迁移，不能清空 V0.1 数据重新建库。

AgentTether 核查重点：初始化是否牵连模型依赖、patch 的安装与卸载、重复包装、异常与输出行为、OpenAI 流式覆盖。已知旧实现跳过 stream=True，不把 token 流纳入承诺；每个 Agent 使用独立进程，避免全局 patch 污染平台进程。复用前检查许可证与再分发条件，不修改外部原仓库。

## 4. 最小数据契约与拟议接口

以下为设计扩展；可执行版本已落地在 `apps/api/live_contracts.py` 和 `packages/contracts/live.schema.json`。会话身份由 Run URL 与写入凭据绑定，事件信封不重复包含 run_id/session_id；服务端补充 received_at。V0.1 导入契约继续支持，不直接重命名旧字段。

| 对象 | 最小新增信息与约束 |
|---|---|
| Run | origin=live/imported、采集能力、开始／结束时间、exit_code、termination_reason；历史来源标签单独保留 |
| CaptureSession | session_id、run_id、collector/adapter_version、last_seen_at、会话状态与发送确认位置；写入凭据只授予当前会话 |
| Event envelope | schema_version、event_id、run_id、session_id、producer_id、producer_seq、occurred_at、received_at、kind、payload；重发沿用原 ID |
| 语义关联字段 | source_span_id、parent_source_id、correlation_id 可选；不以时间相近补造父子关系 |
| 原始证据 | 保存接收时的不可变事件记录及哈希；raw_ref 可追溯到接收记录，日志超限与脱敏需留标记 |
| 数据完整性 | pending/complete/partial/unknown、缺失或截断告警；Agent 退出与采集完成分别记录 |
| Stream cursor | 服务端持久化、Run 内递增的变化游标，覆盖事件追加及状态更新；与源序号分开 |

已实现接口：

- `POST /api/live/runs`：创建 Run 和采集会话，返回写入凭据与网页 URL；请求键保证重试不重复建 Run。
- `POST /api/live/runs/{run_id}/events`：批量写入；重复同 ID 同内容幂等，不同内容冲突；批次校验失败整体拒绝。
- `POST /api/live/runs/{run_id}/heartbeat`：更新会话存活信息，不据此判定任务成功。
- `POST /api/live/runs/{run_id}/finish`：提交退出信息与最终发送序号；缺事件时暂不标记采集完整，允许受限补传后收敛。
- `GET /api/runs/{run_id}/stream`：SSE；通过 Last-Event-ID 或显式游标续接，浏览器刷新也可从持久化数据恢复。

Run 正常运行／正常退出／非零退出／人工中断分别映射 running/completed/failed/cancelled。会话心跳超时只表示失联，保留最后已知执行状态并显示连接告警，不推断 failed 或 passed。工具失败也不自动等于整个任务验收失败。

现有 Run 的 snapshot_hash 面向历史导入；live Run 在采集中不能假称已有最终快照。迁移时区分创建请求的幂等标识与事件快照哈希，结束并补齐数据后再生成明确版本的快照；V0.3 诊断绑定指定快照，不读取持续变化的输入。

服务端按接收游标可靠续传，保留源序号用于重建同一生产者顺序；不同生产者不声称存在严格因果总序。实时追加不可重编号已暴露的游标。现有历史 evidence 定位与哈希保持不变；现场记录只对实际保留的脱敏数据提供哈希，不声称拥有未采集的原文。

## 5. 断线、终止和数据保护

- API 暂不可用：Collector 有限重试，把未确认批次存入被忽略的本机 spool；恢复后以相同 ID 补传。容量、重试及排空超时必须有上限；溢出显式告警并标记 partial，不能无限占用内存或静默丢数据。
- 进程与补传独立：CLI 可在打印待补传位置和处理方法后退出；设计显式补传入口，避免依靠 Agent 重新运行。普通 HTTP 超时后重新发送仍须幂等。
- 网页断线：重连后先补齐持久化变更再继续实时展示；慢客户端不能阻塞写入，游标过期时明确提示重新同步。
- Ctrl+C：向受管理进程传递中断，尽力收集尾部输出并有限排空。CLI 硬杀无法保证 finish，平台用心跳失联状态说明不确定性。不能杀死无关进程。
- 服务重启：保留已接收数据与游标；会话恢复前显示断连。旧数据库升级前备份，迁移失败需可恢复。
- 安全边界：继续绑定回环地址；复用现有同源限制，采集写入使用短期会话凭据，不放进网页 URL、日志或 Git。不把命令执行接口开放到后端。
- 采集范围：不批量收集环境变量、密钥文件或整个工作目录；已知敏感字段在落盘和发送前脱敏，输出设大小上限。脱敏不是无遗漏保证，验收使用可公开的受控任务。

## 6. 页面调整

复用现有页面，不另起一套实时工作台。

- 任务列表：现场／历史来源、运行中状态、最近活动；新 Run 可发现。
- 执行详情：采集连接状态、执行状态、已接收事件、工具开始／返回、日志增量；默认跟随新事件，可暂停跟随，浏览旧记录时不强制跳到底部。
- 证据抽屉：现场事件原始接收内容、关联 ID、时间和脱敏／截断信息。
- 结束状态：区分执行结束、采集尾部待补传、任务验收未知；手动刷新后结果一致。
- 系统页：显示实际采集能力及版本，诊断引擎仍为未接入；未支持的 token 流不能显示为故障。

## 7. 开发顺序与阶段关口

| 阶段 | 产出 | 完成条件 |
|---|---|---|
| A：适配核查与契约 | AgentTether 采集复用矩阵、一个 Python Agent 接入选择、live Schema、状态机与限制 | 结构化工具事件可独立于 HGT 产生；明确所需 SDK／包装改动；无法直接复用时记录依据并采用最小适配 |
| B：接收与持久化 | 数据库迁移、创建 Run、批量事件、心跳、finish、证据及增量关联 | 幂等、冲突、乱序、缺返回、跨 Run 隔离、数据重启保留通过；旧历史样例可读 |
| C：实时页面 | SSE 及游标恢复、详情增量展示、连接和完整性状态 | 任务结束前可看到首个工具事件；网页重连无重复或漏项，原有筛选分页可用 |
| D：CLI 与 Collector | 包安装／启动入口、Agent 包装、输出转发、补传和中断收尾 | 一条命令完成 Run 创建与采集；终端输出、退出码正确，异常不假装成功 |
| E：端到端与交付 | 成功／失败真实执行、故障场景验证、接入与演示说明 | 下列验收清单通过，记录版本、机器配置及测量结果 |

A 阶段先做最小采集验证，D 阶段再完成 CLI 产品化；B/C 可用明确标记的协议夹具验证，但夹具不能替代 E 阶段真实 Agent 验收。不承诺固定完成日期，按关口推进。

## 8. V0.2 验收清单

- [x] 按用户澄清，用确定性 Python 工具 Agent 各执行一条成功任务和失败任务，真实调用本地文件／命令／测试；标记 synthetic，不以历史回放或手工 JSONL 替代现场执行。
- [ ] 真实模型 Agent 兼容性验收：pending，等待用户提供已有授权／本地模型环境；独立于 V0.2 核心验收，不能由确定性测试推断已验证真实模型接入。
- [x] 本地标准演示负载下，工具事件从发生到网页显示的目标 p95 ≤ 2 秒；以至少 100 条事件测量并记录样本量与环境，不宣称生产性能保证。
- [x] 工具开始在返回前可见，异常能定位到证据；Agent 正常退出但验收失败的案例仍显示 failed outcome；没有验收证据显示 unknown。
- [x] 断开网页并重连、刷新页面、重复发送、返回先于调用到达、跨 Run 同名 correlation_id 均有明确且正确的结果。
- [x] API 短暂停止并恢复后，未确认数据可补传；已确认数据重启后保留；队列容量不足时有告警与不完整标记。
- [x] Ctrl+C、非零退出、CLI 硬杀分别展示中断、执行失败、失联／未知，且不把失联冒充验收失败。
- [x] 原 V0.1 后端关键检查和浏览器历史导入链路回归通过；原始资料、日志、spool、凭据不进入 Git。
- [x] 按文档可安装 CLI、启动平台、执行 Agent、打开链接和恢复查看；交付已支持／未支持能力表。

## 9. V0.3 及以后

V0.3 再接真实 AgentTether 诊断：校验权重及依赖、隔离 worker、固定输入快照、记录算法／模型版本、诊断作业超时与失败、报告证据映射。历史导入报告与新推理报告分开存储。存在付费模型需求时沿用用户授权与费用边界，不默认调用。

V0.3 演示目标：真实任务 → 实时轨迹 → 失败 → 真实诊断及证据 → 人工处理并再次执行 → 对照结果。自动执行修复不作为 V0.3 的必要条件；独立验收器的自动编排、受控重试、更广适配及实验评估列入后续版本。
