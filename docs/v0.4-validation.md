# V0.4 Run-centric 工作台验收

2026-09-27 完成。实现范围与状态约束见 [开发计划](v0.4-development-plan.md)。

## 已交付

- 首页优先提供本机 CLI 接入、明确标记的演示入口、运行中、需要处理和其他最近 Run。活动及需处理列表分别有界查询，不会因较新的完成记录挤掉仍在运行的 Run。
- 首页、Task Detail、Run Detail 使用同一只读诊断投影。已有报告而最新诊断作业失败时，既显示已有报告，也显示最新作业失败；不会误写成“尚未诊断”。
- Run Detail 沿执行事实、失败事实及原始证据、待验证根因假设、独立验收、关联运行连续阅读。完整轨迹、报告历史、原始资料与工程字段保留在深入核查。
- Task Detail 仅说明显式归组的多轮历史及前后结果变化；不从先后顺序推断修复因果。单轮导入直接进入 Run，多轮导入进入 Task。
- `origin` 与 `sample_kind` 分别标注。进程执行、任务验收、诊断作业/报告、采集完整性、网页连接分别显示；没有独立验收依据时保持未知。
- 付费 analyst RCA 仍需先离线 HGT、查看实际发送预览，并手动确认。V0.4 不新增自动调用或自动修复，也不增加 Investigation 实体。

## 验证

- `pytest tests/integration -q`：61 通过。覆盖首页有界查询、执行完成但验收失败、导入报告、旧报告与新作业失败并存、现场合成与采集不完整等状态语义。
- `npm run build`：TypeScript 与 Vite 生产构建通过。
- Playwright 对独立本机数据库：5 通过、2 条条件性跳过。通过的路径涵盖历史导入→多轮对照→诊断证据→验收证据、无效导入、真实离线 HGT 作业、CLI 实时采集、SSE 重连/分页与窄屏布局。测试导入使用独立命名空间，避免碰撞已有演示数据。
- 人工抽查空首页、失败 Run、Task 对照及 390px 窄屏；未观察到页面异常或横向溢出。

本轮未发起付费模型请求。真实 LLM Agent 兼容性仍待提供已授权或本地模型环境；已完成 analyst RCA 的专门浏览器用例需要预置记录，因此本次跳过。V0.4 验证的是工作流和状态一致性，不证明诊断准确率或修复因果。

## Run Detail 视觉层级续改（2026-09-27）

仅调整 Run Detail：顶部状态带同时保留执行、任务验收、诊断、采集四个独立事实；明确失败事件优先呈现错误签名及原件入口。主画布显示最近 8 条原始事件，完整轨迹在同一区域按需展开，继续复用搜索、筛选、分页和实时跟随。桌面保留窄幅调查索引，证据侧栏打开时可看到原调查位置；窄屏改单列。根因报告仍按待验证假设呈现，诊断操作仍需 HGT、发送内容预览和人工确认；独立验收继续有自己的结论及原件。

隔离库人工核对历史失败、历史通过、现场运行中和 390px 页面：无页面脚本错误或横向溢出。`npm run build` 通过；浏览器全量先有 4 通过、2 条条件跳过、1 条测试定位失败，定位失败由视觉核查新增的运行中 Run 排到首页首行引起。测试改为按目标 Run 定位后，该专项 2 通过、1 条条件跳过。未改后端 API、Task History 或首页业务布局，也未发起付费模型请求。
