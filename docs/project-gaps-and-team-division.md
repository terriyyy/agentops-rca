# 当前阶段、三人分工与交付计划

更新日期：2026-10-05。

本文明确当前开发阶段、团队成员职责、预期产品效果、交付物与验收标准。待开发内容均为目标要求，不代表现有平台已经实现。

## 1. 当前阶段与共同目标

### 1.1 当前已实现范围

项目目前处于 **V0.4 本地产品原型与真实 Agent 场景集成验证阶段**，已具备：

- 以 Run 为核心的调试工作台、执行轨迹、事件详情及原始证据追溯。
- CLI 启动、显式工具与模型采集、SSE 实时更新、断线补传及独立任务检查。
- 有可靠调用关联的工具 Span、多轮任务历史、前后运行事实对照。
- 离线 HGT 定位、人工预览确认后发起的 RCA 分析，以及工作区模型配置与凭据管理。
- Agent 模型调用和 Token 用量摘要；未记录的数据保留缺失状态。

真实 EnterpriseOps-Gym 邮箱案例已验证两轮执行：第一轮任务检查10/14通过，第二轮14/14通过，记录12次模型请求和17组工具配对。第二轮由原 Agent 的检查反馈机制推动，**尚不是平台将 RCA 反馈注入下一轮 Agent 后实现的修复闭环**。

现有 CLI 可启动并观测进程，但任意 Agent 的工具与模型语义不会自动接入；采集覆盖、RCA准确率、不同框架兼容性和完整修复复验仍需分别验证。

### 1.2 共同目标

围绕明确支持的本地 Python 代码／运维 Agent，完成以下链路：

```text
接入 Agent
    ↓
Run 1：真实执行与实时监控
    ↓
失败事实、独立任务检查与可追溯证据
    ↓
RCA：形成待验证原因与修复建议
    ↓
生成下一轮反馈，人工预览并确认
    ↓
Run 2：接收原任务、失败证据和RCA指导，实际修复并执行
    ↓
独立复验与前后对照
```

同一轮中的多次模型调用和工具执行仍属于一个 Run。本文中的“RCA指导迭代Run”指接续失败运行、实际接收经确认的诊断反馈并再次执行的 Run；普通重跑也会生成新 Run，但应区别标记，不能自动认定为 RCA 指导迭代。

共同原则：执行完成不等于任务通过；诊断不等于验收；RCA为待验证假设；原验收标准不因诊断而降低；不伪造时间、父子关系、证据或成功结论；平台后端不执行用户上传的任意命令；模型调用保持显式确认。

## 3. 徐安：RCA反馈驱动的迭代执行与修复复验

### 3.1 预期产品效果

用户在失败Run查看原因分析后，可以生成下一轮修复反馈，核对反馈内容和原任务约束，确认后通过受支持的本地Agent入口启动下一轮执行。平台明确显示该轮接续哪次失败、使用哪份诊断、实际传入什么反馈，以及最终执行与检查结果。

用户无需手工从多个页面复制诊断文字再自行拼接，也不会因点击“生成反馈”就直接产生实际执行或付费调用。

### 3.2 反馈与Prompt组织

下一轮输入应保留原Agent系统指令、原任务目标和原验收要求，并加入一份结构化反馈：

| 内容 | 要求 |
|---|---|
| 原任务 | 保持任务目标与约束；任务目标发生实质变化时不得继续当作同一任务修复 |
| 上轮失败事实 | 已记录的失败检查、异常与必要上下文；区分执行错误和任务检查失败 |
| RCA候选原因 | 标明待验证、不确定性及适用边界；不能改写为确定结论 |
| 相关证据 | 可追溯到上一轮真实事件、输入输出或检查记录；未解析引用明确说明 |
| 修复指导 | 先检查什么、建议修改范围、需要保留的行为；避免无关改动 |
| 复验要求 | 重跑原检查，并按需要加入定向检查；不能用RCA文字代替检查结果 |

应使用 Agent 实际支持的反馈消息或输入接口接入，不强制把所有框架统一成同一种完整Prompt模板。已有对话历史保留还是新建执行上下文，应明确记录，不能声称Agent获得了实际未传入的历史内容。

反馈支持人工预览、编辑、取消和确认；保存最终确认版本。内容超过输入限制时显示取舍与截断情况，不静默丢失关键失败证据。密钥、认证头及无关私有内容不得进入反馈。

### 3.3 实际执行与关系记录

- 后续Run与上一轮属于同一Task，具有新的独立run_id、事件与检查记录。
- 显式保存前一Run、所选诊断、确认后的反馈及实际启动信息；不能仅按轮次相邻推断来源。
- 区分“反馈已生成”“已确认”“Agent已启动”“执行已结束”“复验结果”；生成、编辑或取消反馈均不等于已执行。
- 通过本地CLI／受支持适配器执行Agent；网页负责准备和展示，后端不运行上传的任意命令。
- 接入方实际收到的反馈应与确认版本一致，可通过内容摘要或哈希校验；未传入或未启动不得展示为RCA指导执行。
- 普通重跑、Agent原生检查反馈迭代和平台RCA指导迭代分别注明来源。
- 后续轮次仍未通过时保留真实失败，可重新分析并生成下一次反馈；默认不无限自动重试，执行次数与模型预算需受控。

### 3.4 独立复验与结果展示

页面应能回答：上一轮哪里失败、采用了什么指导、下一轮实际做了什么、原检查是否通过、仍有哪些问题未验证。

若修改了代码或配置，应记录真实变更摘要及可追溯依据；没有可靠变更记录时显示未记录，不根据诊断建议虚构修改。复验由原测试／validator／检查程序实际执行并上报。

“任务检查通过”与“根因假设得到支持”分开表达。只有原失败消失且具备相应定向证据，才能说明该假设受到本次结果支持；不能仅凭最终passed认定RCA原因已证实。执行失败、检查未知、采集不完整和修改无效均保留相应状态。

### 3.5 交付物与验收标准

交付：反馈构建与预览交互、Agent反馈消费入口、前后Run/诊断/反馈的关系记录、复验与对照展示、可复现示例及相关测试。

必须验收：

1. 一条真实代码Agent的失败→RCA→确认反馈→实际修复→后续Run→独立检查通过链路；无模型synthetic示例先验证协议与界面。
2. 核对后续Agent确实收到确认的反馈，而非仅创建记录或原样重跑。
3. 取消反馈不启动；启动失败、用户中断、修改无效和检查unknown不会显示修复成功。
4. 后续Run可回查前一Run、诊断和最终反馈，原始事件与验收证据保留。
5. 所有工具执行成功但任务检查失败时，也能构建基于真实检查证据的下一轮反馈。

## 4. 陈志敏：Agent接入与采集可靠性

### 4.1 预期产品效果

对声明支持的Agent，新用户完成一次安装和入口配置后，可通过一条命令启动Agent并获得Run链接；网页在运行期间持续显示模型调用、工具调用与返回、日志、异常及任务检查。

“一条命令”必须建立在明确的适配和覆盖范围上，不能把仅采集stdout称为完整Agent监控。接入过程不要求用户理解HGT、RCA或安装HGT权重。

### 4.2 接入与预检

- 优先固定一种主入口及其支持版本，例如OpenAI Chat Completions或LangChain；提供完整示例、配置方式和兼容清单。
- 将必要的对象包装／适配配置集中到入口，避免用户在每个工具函数中重复埋点；特殊框架的必要改动明确说明。
- 复用现有CLI、SDK与AgentTether桥接，不以重新编写整套采集系统为目标。
- 启动前检查平台连接、适配器、目标入口、依赖和配置；不支持或缺失时给出具体信息，允许明确的process-only降级。
- 启动后打印Run链接，并核对上报是否真正到达；API在线不能等同Agent已接入。

### 4.3 采集数据要求

| 信号 | 预期记录与表达 |
|---|---|
| 工具 | 名称、必要参数、返回/错误、真实起止或测量耗时、可靠correlation；未知状态保留unknown |
| 模型 | 模型名称、请求/响应、真实调用关联、可用usage与耗时；缺失Token不填零 |
| 日志 | 真实来源、时间与内容；不把普通日志画成持续Span |
| 检查 | 检查来源、依据、expected/actual及passed/failed/unknown；与进程退出分开 |
| 采集范围 | 明确已支持、不支持、只观察到结束或采集失败；与事件是否完整交付分别记录 |

同一次逻辑调用不能因高层Agent、LangChain、OpenAI或MCP多层挂钩而重复计数。工具Call/Return仅在可靠ID下配对；parent和模型区间仅在真实数据充分时生成。输入输出经过脱敏和限长，保留必要的来源与限制说明。

完整流式采集作为补充目标：记录真实开始、已消费输出、结束、提前关闭、异常与取消，说明最终usage是否提供；事件实时更新和逐token输出不能混为一谈。

### 4.4 可靠性与协作接口

断连补传保持幂等；重复批次不重复计数；finish先到时等待未补齐记录，不能提前宣称完整。采集器崩溃、进程中断、丢弃和取消应可解释，采集失败不得静默改变Agent业务行为。

向徐安提供：启动/反馈消费的适配边界、真实新Run创建与同Task归组、执行状态、检查上报以及调用关联信息。向林亦航提供：可复现的诊断输入轨迹、明确覆盖范围、截断和缺失信息。诊断输入不得因采集侧准备而混入隐藏真值答案。

### 4.5 交付物与验收标准

交付：接入配置/入口、CLI预检、支持版本表、最小接入文档、无模型自检、Mock兼容与可靠性测试，以及真实Agent验收记录。

必须验收：

1. 干净环境完成一次配置后，受支持Agent可一命令启动并实时查看Run。
2. 实际工具调用与返回逐项核对，模型调用数和usage口径明确；没有重复采集或按时间猜测配对。
3. 同步/异步、异常、取消、断连补传、重复上报和启动失败的状态正确。
4. 凭据不进入采集事件；原件、来源和质量限制可追溯。
5. 缺算法权重仍可监控；不支持入口明确降级，不能展示虚假的完整覆盖。
6. 真实Agent测试按受控模型配置与预算执行，Mock测试不冒充真实兼容验收。

## 5. 林亦航：RCA算法评测与优化

### 5.1 预期效果

平台能够基于真实失败轨迹定位候选步骤、提出有证据支持且边界明确的原因，并生成适合下一轮Agent使用的修复与验证建议。效果通过可复现实验衡量，不以权重成功加载、生成报告或个别任务修复成功作为准确率证明。

### 5.2 基线、数据与评测

- 固定AgentTether源码、HGT bundle、模型/adapter版本及输入处理口径，建立原算法基线。
- 建立带根因、关键步骤、证据与原检查结果的案例集，初步覆盖10–20个案例；按失败类型和输入适用性分别统计。
- 覆盖工具异常、错误参数/路径、超时、状态污染及所有工具成功但任务失败；加入成功轨迹检验误报。
- 人工核对标注，允许多原因或无法确定的情况；区分诊断可见证据和仅用于评价的隐藏答案。
- 区分用于开发调试、参数选择和最终评测的数据，避免只在同一案例反复调优后宣称泛化。

### 5.3 优化内容

优先核对输入完整性、HGT候选选择、转折点与事件映射、上下文截断、analyst提示及证据校验。对证据不足或HGT输入不适用的情况，明确输出限制，不强行给出确定根因。

根据评测结果比较原HGT、HGT＋LLM及必要的LLM-only研究对照；保持相同可见输入和模型配置，记录每次策略差异。研究对照不自动替换现有生产流程。参数调整、权重更新或训练需有明确失败类型、收益与回归依据。

面向徐安提供稳定的诊断消费格式：事实摘要、候选原因、证据引用、限制、建议检查/修改范围及验证建议。原始报告与算法来源保留，高级算法字段不直接成为用户必须理解的修复步骤。

### 5.4 指标与交付

指标至少包含：有明确标注时的步骤Top-k命中、无故障误报、原因描述正确性、证据支持程度、证据不足时的不确定性处理、诊断输入适用率、执行时延、模型调用和Token量。缺失usage不估成零；费用仅按有依据的实际价格口径计算。

交付：案例与标注说明、基线脚本、分类型结果表、优化前后对照、失败分析、版本记录，以及供迭代模块消费的诊断结果规范。

必须验收：

1. 同一固定输入与版本可以复现实验，基线与优化策略可区分。
2. 引用可回到真实事件，未解析引用明确显示，不伪造支持证据。
3. 隐藏验收答案未泄漏到诊断Prompt；不支持输入和失败作业未被静默排除。
4. 改进具有明确指标或案例证据，并列出退化及适用范围，不保证所有case均能定位。
5. RCA提出的原因不改变Task Outcome，修复建议不冒充已经执行的修改。

- 共同确认反馈来源、确认版本、Agent实际消费、前后Run、真实时间、覆盖范围、取消、usage与检查口径。

## 7. 开发交接要求

技术操作见[团队开发交接](team-development-handoff.md)。交接材料包括：

1. **代码与版本**：仓库权限、远端可获取的commit SHA、分支、启动说明及相关测试。
2. **私有依赖**：林亦航使用获授权源码与匹配HGT bundle；陈志敏使用AgentTether桥接时需要私有采集源码，但不需要HGT权重；徐安可用合成报告开发交互，真实联调接入受控算法环境。
3. **本地配置**：各自Agent配置、RCA连接和独立数据库；不复制其他成员的.env、加密凭据或整个私有运行目录。
4. **样例与证据**：合成夹具、审查后的脱敏真实片段、预期检查结果及复跑前置条件；clone代码不会获得既有本地Run记录。

各成员应独立启动平台，运行无模型示例并验证实时事件、工具配对、任务检查和原件追溯。真实Agent复跑需准备原源码/case、测试环境、授权模型与预算，旧临时端口和已清理容器不能直接复用。

交接应采用包含本次配色与实名分工修订的提交版本；本地提交不表示GitHub已更新，分发前需确认远端可获取的完整commit SHA。本文列明开发目标，不表示已完成迭代功能、服务器部署或模型调用。

## 8. 范围限制与共同验收

近期交付以明确支持的一种Agent、可复现诊断和人工确认的反馈迭代为范围。全部框架自动发现、无限自动迭代、无确认付费调用、多租户SaaS及无评测依据的重训不作为本次分工的完成条件。

共同验收必须证明同一条真实案例串联了三个模块：采集提供失败证据，诊断产生有来源的指导，Agent实际接收确认反馈并产生后续Run，独立检查给出复验结果。保留失败、未知和无效修改场景，不能只展示成功路径。

一个本地工作区RCA连接不等于成员账户的私人连接；共享服务器部署前应明确账户/权限、配置归属与计费边界，或为成员使用独立实例。
